# 需求確認文件

> **給開發人員用**：複製本文件 → 填寫或列印 → 帶去與用戶開會逐項確認。  
> **原則**：Must 沒定案不估時；沒有驗收標準不算需求完成。

---

## 使用方式

| 時機 | 你要做的事 |
|------|-----------|
| **開會前** | 複製模板、填基本資訊、標出你已知的 Must / 待確認 |
| **開會中** | 逐章走；每個 Must 問「沒有這個能不能上線？」 |
| **開會後** | 寄用戶摘要 + Open Questions 截止日期 |
| **開發前** | 所有 Must 都有驗收標準，用戶書面或 email 確認 |

**文件狀態**：`草稿` / `待確認` / `已確認` / `已變更（見第 14 章）`

## 附錄 A：30 分鐘快速對需求 Checklist

**開會前 5 分鐘（你自己）**

- [ ] 基本資訊已填
- [ ] 已知 Must 至少列 3 項
- [ ] 已準備 2 個「這次不做」的例子，避免 scope 膨脹

**開會中 20 分鐘（與用戶）**

- [ ] 決策者是誰（第 1 章）
- [ ] 成功指標一句話（第 2 章）
- [ ] 角色與主要流程各 1 條（第 3、5 章）
- [ ] Must 功能清單逐項確認（第 4 章）
- [ ] 內容誰提供、何時交（第 6 章）
- [ ] 至少 2 項 Out of Scope 寫死（第 10 章）
- [ ] Open Questions 有負責人與截止日期（第 13 章）

**開會後 5 分鐘（你自己）**

- [ ] 當天寄出會議摘要
- [ ] Must 缺驗收標準的補齊
- [ ] 等用戶確認後才開始 Phase 1 開發
